# SmartKey Design System

This folder is the **source of truth** for SmartKey's visual design and user-facing structure.

## Files

- **`DESIGN.md`** — The visual design system in Google Labs' DESIGN.md format. YAML front matter (machine-readable design tokens) + Markdown body (human-readable rationale). Validated by `@google/design.md` CLI. Loaded by Stitch as persistent context. Drives the Tailwind config and `globals.css` for the codebase.
- **`screens.md`** — Information architecture, user flows, screen specifications, AI surfaces, notification rules, state catalogue. Source for the per-screen prompt files. Reference when designing new screens.
- **`prompts/`** — Per-screen prompt files for Stitch (one per screen, ready-to-paste).
- **`tailwind.theme.json`** — Generated by `bun run design:export`. Do not edit by hand.
- **`tokens.dtcg.json`** — W3C Design Tokens Community Group format. Generated by `bun run design:export`. Consumed by Figma plugins, Style Dictionary.

## Workflows

### Designing a new screen

1. Add the screen to `screens.md` under the appropriate role section.
2. Add a per-screen prompt file in `prompts/<role>/` following the existing pattern.
3. Use Stitch with that prompt to generate the design.
4. Implement following the `new-screen` slash command.

### Updating design tokens

1. Edit `DESIGN.md` directly.
2. Run `bun run design:lint` — must return zero errors.
3. Run `bun run design:export` — regenerates Tailwind + DTCG.
4. Run `bun run design:sync` — applies to `globals.css` and `tailwind.config.ts`.
5. Run `bun run typecheck && bun run test:e2e` to verify nothing broke.

`design:lint`/`design:export`/`design:sync` are not real `package.json` scripts today (see `CLAUDE.md`'s Commands section) — this workflow is aspirational until they're wired up. To lint `DESIGN.md` right now, run `bunx @google/design.md lint DESIGN.md` directly.

### Cross-tool consistency

Stitch reads DESIGN.md directly. The codebase uses tokens generated from it. Figma can import tokens via the DTCG export. Cursor and Claude Code see DESIGN.md via the project context. One file, one truth.
