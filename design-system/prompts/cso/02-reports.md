## Project Context

SmartKey is a four-role web application replacing the paper-based key management workflow at the University of Lagos Senate Building. The roles are:

- **Chief Security Officer (CSO)**: senior administrator. Desktop-primary. Oversight, reports, audit log, user management.
- **Head of Department (HOD)**: faculty member. Mixed device usage. Authorises up to three collectors per departmental key, signs weekend approvals.
- **Verifier (security personnel)**: 24/7 desk staff in 8-hour shifts. Shared desktop at the security desk. Issues and receives keys, performs shift handover.
- **Requester (university staff)**: lowest-frequency user. Phone-primary. Requests a key, receives a 6-digit code by email, presents it at the desk.

Three AI components run in the background: rule-based risk scoring (visible to verifiers as Low/Medium/High tier), Gemini-generated shift reports (CSO dashboard), and pixel-level signature verification (HOD signed approvals). WCAG 2.2 AA conformance is the floor. Use the SmartKey design system from DESIGN.md — do not invent colours, typography, or component styling.

## CSO area routes

- `/cso` — Dashboard home (live key counts per zone, anomaly alerts, today's events)
- `/cso/reports` — Generated shift reports (Gemini-produced); download, comment
- `/cso/audit` — Searchable, filterable audit log of every event
- `/cso/users` — User management (provision new accounts, deactivate)
- `/cso/keys` — Key inventory across both zones; create / retire key records
- `/cso/settings` — Operational hours, risk-rule weights, profile, theme

## Flow: CSO reviews a generated shift report

1. On `/cso/reports`, tap the latest report card.
2. Read the Gemini-generated summary; expand the embedded ShiftTimeline if needed.
3. Add comments (saved as immutable audit additions) and download as PDF.

The report itself is immutable; the CSO can add comments but cannot edit the generated text.

## AI surface: Gemini-generated shift reports

- **Treatment**: long-form readable card with sections: outstanding keys, flagged events, unresolved incidents, chain-of-custody summary. Body-md prose; embedded ShiftTimeline for visual log.
- **Editing**: report itself is immutable. CSO can add comments (timestamped, signed) and download the comments alongside as a single PDF.
- **Disclosure**: small caption at foot of every report: "Generated by AI from shift event data".

## Generation request

Generate two screens: the reports list and a single report detail.

**Screen 1 — Reports list (`/cso/reports`)**:
Layout: page heading "Shift Reports" with a primary "Generate report now" button on the right. Reports rendered as a vertical list of cards, one per shift, reverse-chronological, grouped by day with sticky day headers.

Each report card: shift number (e.g., "Shift 3 — Wed 30 April 2026, 16:00–00:00"), officer names ("Officer Musa, Officer Adeleke"), summary stats inline (e.g., "8 keys issued · 7 returned · 1 flagged"), and a small "AI-generated" caption. Tap the card to open the detail.

Filter chips at top: "All", "Last 7 days", "Last 30 days", "Has incidents", "Has anomalies". Search input on the right.

Empty state if no reports: "No shift reports generated yet." with a "Generate now" button.

**Screen 2 — Report detail (`/cso/reports/:id`)**:
Layout: full-width report on a centred max-width 800px column. Top of page: shift metadata (number, date range, officers), download PDF button, and a "View underlying events" link to the audit log filtered to this shift.

The Gemini-generated report renders as long-form prose in body-md with section headings. Required sections in this order:

1. **Summary** — 2–3 sentences overview.
2. **Outstanding keys at end of shift** — list with key code, room, collector, time issued.
3. **Flagged events** — list with event type, time, brief context, link to audit record.
4. **Unresolved incidents** — list, or "None" if empty.
5. **Chain-of-custody summary** — table of every key movement during the shift.

Embedded **ShiftTimeline** above the chain-of-custody section: vertical timeline of all events in the shift, one node per event, colour-coded by type.

**Comments section** below the report: existing CSO comments listed as a thread (each with author, timestamp, text), plus a textarea + "Add comment" button at the bottom. Comments are immutable once posted (note this in helper text below the textarea).

Footer: small caption "Generated by AI from shift event data on [timestamp]. Comments are auditable additions and do not modify the report."

Use placeholder data for a realistic shift with 8 keys issued, 1 high-risk flag, 1 unresolved incident. Generate at 1440px (desktop) and 390px (mobile).
