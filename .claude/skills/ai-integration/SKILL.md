# AI integration

SmartKey has three AI components. Each lives under `src/lib/ai/` and surfaces in the UI under specific rules.

## 1. Risk scoring engine (`src/lib/ai/risk/`)

Rule-based, not learned. A pure TypeScript engine that takes a request context and returns a score and contributing factors.

```ts
type RiskInput = {
  requesterId: string;
  keyId: string;
  requestedAt: Date;
  isWeekend: boolean;
  hasOutstandingKey: boolean;
  recentRequestCount: number;
  isWhitelisted: boolean;
};

type RiskFactor = {
  rule: string;
  description: string;
  weight: number;
};

type RiskOutput = {
  tier: 'low' | 'medium' | 'high';
  totalScore: number;
  factors: RiskFactor[];
};

export const evaluateRisk = (input: RiskInput): RiskOutput => {
  /* ... */
};
```

Rules are defined in `src/lib/ai/risk/rules.ts` with their weights. Tier thresholds are in `src/lib/ai/risk/thresholds.ts` and configurable from the CSO settings page. Changes to weights and thresholds affect new requests only — historical scores are not recomputed.

**UI surface**: `<RiskTierBadge tier={output.tier} factors={output.factors} />` on the verifier dashboard. Factors are revealed via "View factors" popover. High-risk requests gate the issue flow with an explicit acknowledgement step.

**Tests**: every rule has a unit test in `src/lib/ai/risk/rules.test.ts` with positive and negative cases. The engine itself has integration tests covering tier transitions.

## 2. Gemini-generated shift reports (`src/lib/ai/reports/`)

Generated by Google Gemini from the raw audit log of a shift. Pattern:

```ts
import { generateShiftReport } from '@/lib/ai/reports';

const report = await generateShiftReport({ shiftId });
// report.markdown is the generated prose
// report.timeline is the structured ShiftTimeline data
// report.metadata includes shift number, officers, generated_at
```

The function:

1. Fetches all audit log entries for the shift (RPC, server-side only).
2. Calls Gemini with a structured prompt template (in `src/lib/ai/reports/prompts.ts`).
3. Parses the structured response (JSON + markdown).
4. Stores the report in the `shift_reports` table — **immutable**.
5. Writes an audit entry: `report_generated`.

**Constraints**:

- Reports are generated server-side only (Gemini API key is never on the client).
- Reports are immutable. The CSO can add **comments** (separate audit entries) but cannot edit the prose.
- Every report carries a "Generated by AI from shift event data" disclosure caption.

**UI surface**: long-form readable card on `/cso/reports/:id`. The CSO can download as PDF (the comments are appended).

## 3. Signature verification (`src/lib/ai/signature/`)

Pixel-level matching using Sharp (image preprocessing) + Pixelmatch (comparison).

```ts
import { verifySignature } from '@/lib/ai/signature';

const result = await verifySignature({
  reference: hodReferenceBuffer, // stored on HOD onboarding
  submitted: incomingBuffer, // signature embedded in the approval
});
// result.match: boolean
// result.mismatchPercentage: number
// result.threshold: number (configurable, default 15%)
```

Pipeline:

1. **Sharp**: greyscale, normalise resolution to 800×400, threshold to binary.
2. **Pixelmatch**: pixel-by-pixel diff between the two binary images.
3. Compute mismatch percentage; compare to threshold.

**Constraints**:

- Runs server-side only (uploaded buffers never sent to the client).
- On match: silent — log audit entry "signature_verified", proceed.
- On mismatch: hold the approval, write audit entry "signature_mismatch", surface alert on CSO dashboard with reference + submitted + percentage shown side by side.

**UI surfaces**:

- HOD onboarding: two-pane preview showing the original upload and the post-Sharp processed reference.
- CSO mismatch alert: detailed view showing reference, submitted, percentage, link to underlying request.

## Common cross-cutting rules

- **All AI calls are server-side**. Never put API keys on the client.
- **All AI outputs are inspectable in the UI**. Never present an AI decision as opaque. Risk → factors expandable. Reports → readable prose, downloadable. Signature → reference and sample side-by-side on mismatch.
- **AI outputs feed audit log entries**, not the other way around. The audit log is the source of truth; AI consumes it (reports) or annotates it (risk factors).
- **AI does not gate operationally critical paths automatically**. High-risk requests need verifier acknowledgement; signature mismatches need CSO action. The human decides.

## Testing AI components

- **Risk engine**: pure-function unit tests, deterministic. Cover every rule and tier boundary.
- **Reports**: snapshot tests with fixture audit logs and recorded Gemini responses (use `@/test/fixtures/gemini` mocks; never call live API in CI).
- **Signature**: fixture image pairs in `src/lib/ai/signature/fixtures/` covering match, threshold-edge, mismatch.
